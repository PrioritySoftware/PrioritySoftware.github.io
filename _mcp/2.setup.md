<a name="Setup"></a>
## Setup & Configuration

<a class="anchor-link" name="Endpoint"></a>
### Endpoint

The Priority MCP Server is available on Priority's cloud platform via streamable HTTP transport.

| Environment | URL |
|-------------|-----|
| Production | `https://p.priority-connect.online/mcp/erp` |
| Testing (Europe) | `https://t.eu.priority-connect.online/mcp/erp` |
| Testing (US) | `https://t.us.priority-connect.online/mcp/erp` |

Use the testing environment URL that matches your testing tenant's region. Use the production URL for live data.

<a class="anchor-link" name="Authentication"></a>
### Authentication

Authentication is handled via HTTP headers sent with every MCP request.

**Required Headers:**

| Header | Description |
|--------|-------------|
| `prettyname` | Your Priority ERP tenant name, derived from your Priority URL. For example, if you access Priority at `https://p.priority-connect.online/webui/bt23u/`, your tenant name is `bt23u`. |
| `Authorization` | Credentials using a Personal Access Token (see below) |

<a class="anchor-link" name="Creating_a_Personal_Access_Token"></a>
### Creating a Personal Access Token

Authentication uses a Priority **Personal Access Token (PAT)**, not your interactive login password. PATs are managed in the **PATOKENS** form inside Priority:

1. Log in to Priority (web or desktop client) for the relevant tenant.
2. Open the **PATOKENS** form (Personal Access Tokens) -- you can find it using the forms search bar.
3. Create a new record:
   - Give it a description to identify its purpose (e.g., `MCP integration`).
   - Set an expiration date if required by your organization's policy.
4. Save the record. Priority generates the token value on save -- copy it immediately, as it is only shown once.

Treat the PAT like a password: store it securely and revoke it from the PATOKENS form if it is ever exposed.

<a class="anchor-link" name="Building_the_Authorization_Header"></a>
### Building the Authorization Header

Build the credential string as:

```
<PAT_TOKEN>:PAT
```

Where `<PAT_TOKEN>` is the token value from the previous step, and the password field is the fixed literal string `PAT`.

Base64-encode that string and use it in the `Authorization` header:

```bash
echo -n "<PAT_TOKEN>:PAT" | base64
```

**Example:**

If the generated PAT is `abc123XYZ`:

```bash
echo -n "abc123XYZ:PAT" | base64
# Output: YWJjMTIzWFlaOlBBVA==
```

The resulting header:

```http
Authorization: Basic YWJjMTIzWFlaOlBBVA==
```

<a class="anchor-link" name="Client_Configuration"></a>
### Client Configuration

Below are configuration examples for common MCP clients.

<a class="anchor-link" name="Claude_Code"></a>
### Claude Code

Add to your project's `.mcp.json` or global MCP settings:

```json
{
  "mcpServers": {
    "priority-mcp": {
      "type": "streamableHttp",
      "url": "https://p.priority-connect.online/mcp/erp",
      "headers": {
        "prettyname": "bt23u",
        "Authorization": "Basic YWJjMTIzWFlaOlBBVA=="
      }
    }
  }
}
```

Replace `bt23u` with your tenant name and the Authorization value with your Base64-encoded PAT credentials.

<a class="anchor-link" name="Cline"></a>
### Cline

Add to your Cline MCP settings (`~/.cline/mcp_settings.json`):

```json
{
  "mcpServers": {
    "priority-mcp": {
      "autoApprove": [],
      "disabled": false,
      "timeout": 60,
      "type": "streamableHttp",
      "url": "https://p.priority-connect.online/mcp/erp",
      "headers": {
        "prettyname": "bt23u",
        "Authorization": "Basic YWJjMTIzWFlaOlBBVA=="
      }
    }
  }
}
```

<a class="anchor-link" name="Other_MCP_Clients"></a>
### Other MCP Clients

Any MCP client that supports streamable HTTP transport can connect. Configure it with:

| Setting | Value |
|---------|-------|
| Transport | Streamable HTTP |
| URL | `https://p.priority-connect.online/mcp/erp` |
| Headers | `prettyname` (your tenant name) and `Authorization: Basic <encoded PAT>` |
| Timeout | 60 seconds recommended |
